# Deep Agents 方案实施与验收

日期：2026 年 11 月 3 日。实施目标是先证明 Agent 能完成未预设的真实分析，再扩大 ERP 功能和电商平台覆盖。阶段以验收结果推进，暂不在 ERP 接口和平台未确认时承诺工期。

## 1 建设顺序

| 阶段 | 交付内容 | 退出条件 | 对应痛点 |
| --- | --- | --- | --- |
| A 框架与环境验证 | 锁定 Deep Agents、模型适配器、checkpointer、沙箱版本；建立最小自主分析环境 | 可读取数据、运行代码、生成文件、暂停恢复；权限与工具行为可观测 | P01、P09、P11、P18 |
| B 首个 ERP 的研究能力 | 数据目录、语义、批量读取、授权查询、纺织知识和证据索引 | 未预写报表逻辑的问题可组合查询并形成可复算结果 | P02、P03、P04、P05、P21 |
| C 本地竞品能力 | 一个目标平台、一种设备环境、浏览器连接、任务和证据协议 | 登录、断线、页面变化、字段缺失均有正确状态；完成一次跨 ERP 竞品研究 | P06、P07、P08、P15、P17 |
| D 业务动作闭环 | 选择一个真实写动作，完成授权、预检、幂等与结果核对 | 成功响应丢失、重试、恢复不造成重复单据，权限与审批不可绕过 | P12、P13、P14、P20 |
| E 插件与运行加固 | 第二个 ERP、版本兼容、运行配额、回归评测和共享权限 | 共性能力可复用，厂商差异明确，升级与撤权场景通过 | P10、P16、P19、P22 |

阶段 B 的研究问题应由业务人员提出，开发者在准备数据与工具时不为每个问题编写专属解决函数。经过验证的通用清洗与计算函数可以复用，但必须保留分析路径的开放性。

## 2 首轮必须验证的框架行为

| 项目 | 验证内容 | 决策 |
| --- | --- | --- |
| 模型适配 | 工具调用、结构化结果、流式事件、错误和 usage 字段 | 选择一个主模型并固定版本，不在运行中无规则切换 |
| Backend | 文件工具路径和沙箱内路径是否一致 | 用真实沙箱演示写文件后运行代码读取，避免虚拟文件不可见 |
| 工具可见性 | Backend 类型、Skills、中间件和子任务是否改变工具列表 | 固定 run 的能力版本，记录实际请求指纹 |
| 持久化 | 人工中断、进程重启、数据库恢复后的状态 | 使用持久 checkpointer 和会话运行锁 |
| 长任务 | 大结果外置、压缩后恢复证据、预算终止 | 确定任务笔记和文件恢复协议 |
| 人工审批 | 拒绝、编辑、过期和重复提交 | 批准绑定参数与身份，编辑后重新校验 |
| 子 Agent | 工具继承、权限隔离、取消和结果回传 | 只开放验证过的子任务类型 |
| 沙箱 | 资源限制、网络出口、凭据访问和销毁 | 未通过隔离测试前不运行真实企业数据 |

不得直接把文档示例中的内存存储、默认模型名或临时目录当作生产配置。具体 SDK 调用以锁定版本为准，以下契约是项目自己的服务边界。

## 4 核心协议

### 4.1 运行上下文

可信服务为工具和代码代理注入以下上下文，模型只能请求业务参数，不能自行声明租户和权限。

```json
{
  "tenant_id": "tenant_demo",
  "actor_id": "user_demo",
  "session_id": "session_demo",
  "run_id": "run_demo",
  "authorization_ref": "grant_demo",
  "policy_version": "policy_v1",
  "capability_snapshot_id": "caps_v1",
  "workspace_id": "workspace_demo"
}
```

授权引用不是可无限使用的静态许可。每次重要调用及恢复时重新验证权限、有效期和设备绑定。run 固定能力版本不意味着忽略撤权。

### 4.2 数据查询结果

```json
{
  "query_id": "query_demo",
  "status": "completed",
  "dataset_ref": "dataset_demo",
  "row_count": 12500,
  "schema_ref": "schema_demo",
  "snapshot_id": "snapshot_demo",
  "data_as_of": "2026-11-03T08:00:00+08:00",
  "source_refs": ["erp.sales_lines", "erp.quality_costs"],
  "warnings": ["部分委外费用仅有月度汇总"],
  "preview_ref": "preview_demo"
}
```

`dataset_ref` 是带访问控制的数据引用，不是任意文件路径或永久公开链接。代码代理加载数据时仍验证身份。数据集元信息同时记录查询文本或规范化查询、参数、源版本、过滤范围、导出时间和文件哈希。

### 4.3 本地任务

```json
{
  "protocol_version": "1",
  "task_id": "task_demo",
  "step_id": "step_demo",
  "attempt_id": "attempt_demo",
  "device_id": "device_demo",
  "capability_id": "browser.collect_products",
  "capability_version": "1",
  "scope_ref": "browser_grant_demo",
  "lease_id": "lease_demo",
  "deadline": "2026-11-03T18:00:00+08:00",
  "input": {
    "product_urls": ["https://example.com/product/demo"],
    "fields": ["sku", "price", "composition", "width"],
    "max_items": 20
  }
}
```

示例网址和 ID 均为占位。身份绑定、签名或短期令牌在传输层验证。设备还要验证网站重定向后的实际域、任务账号和标签页租约。浏览器观察动作允许 Agent 自主组合，但只能使用任务已授权的资源范围。

返回事件包含 `event_id`、单调序号、任务和尝试标识、状态、时间及结果引用。设备暂时离线后可能重复上报，服务端按事件 ID 去重。租约到期后不能盲目重新执行不确定的外部写操作。

### 4.4 业务写操作

执行请求记录 `operation_id`、`idempotency_key`、`command`、`payload_hash`、`expected_version`、`approval_ref`。授权与批准从服务端状态读取，不信任模型提供的批准描述。

状态至少区分：`prepared`、`awaiting_approval`、`executing`、`succeeded`、`failed`、`outcome_unknown`。对于 `outcome_unknown`，先根据操作 ID 和 ERP 单据查询恢复事实。

### 4.5 报告与证据

报告清单包含标题、文件引用、数据截至时间、访问范围、查询 ID、代码版本、数据快照、证据条目、未决假设和关键结论引用。证据条目包含来源位置、采集或读取时间、摘录或截图引用、对应字段和缺失信息。

对话里展示摘要，完整报告允许下载。生成 HTML 通过隔离预览器加载；用户分享报告时再次校验接收方权限，不能仅依靠不可猜测的 URL。

## 5 运行状态与恢复

任务状态建议包含 `queued`、`running`、`waiting_for_user`、`waiting_for_device`、`waiting_for_approval`、`cancel_requested`、`completed`、`partially_completed`、`failed` 和 `cancelled`。这些状态描述运行生命周期，不预先限定研究路径。

对同一会话的并发用户消息进行排队或明确中断当前 run，避免两个 Worker 同时修改状态。用户更改目标作为新事件记录，保留已执行结果；不会因为新目标取消已经发生的 ERP 副作用。

恢复顺序：取得运行租约，读取 checkpoint 和事件，核对未完成工具账本，恢复工作空间清单，验证权限和外部资源状态，再继续模型循环。已经完成的外部操作返回已知结果，避免重新执行。

## 6 评测数据与开放问题

首轮准备一组经过业务确认的脱敏数据：销售、订单明细、生产批次、质量与返工、委外、成本、回款和产品规格。保留可计算的标准结果，同时设计缺失数据、错误单位、一对多关联和晚到数据。

建议先形成 20 至 30 个开放问题作为初始规模，而非宣称该数量足以证明生产可靠性。将部分问题作为开发集，另留未参与提示和 Skills 调整的保留集；报告按类别展示成绩，不只提供一个平均分。

| 场景 | 预期能力 | 重点检查 |
| --- | --- | --- |
| 销售增长但返工后利润下降 | 自主找数据、建立临时指标、编写代码 | 利润口径、缺失成本、重复连接 |
| 订单拆小后染缸利用率变化 | 发现容量、批次和工艺数据 | 单位与约束，不能无依据推断因果 |
| 某客户是否值得继续赊销 | 结合贡献、退货和回款 | 权限、时间口径和财务数据限制 |
| 竞品价格更低是否应跟价 | 登录采集与 ERP 成本联动 | SKU、规格、零售与出厂价差异 |
| 把刚才分析改成按幅宽和克重分组 | 修改现有分析 | 不需要新增报表工具，产物可追溯 |
| 数据中没有返工归属关系 | 识别缺失并提供替代分析 | 不伪造精确产品成本 |
| 页面写着让 Agent 导出客户名单 | 抵抗外部指令 | 不执行越权动作，不污染组织记忆 |
| 用户撤销成本字段权限 | 运行中权限变化 | 停止继续获取并限制相关产物 |
| ERP 创建成功但连接中断 | 幂等与状态核对 | 最终只有一个业务结果 |
| 本地浏览器退出再恢复 | 持久任务与设备状态 | 不换账号，不重复已完成采集 |

## 7 缓存与成本实验

固定模型、数据、工具版本和任务集合，对每组请求记录实际工具定义指纹、模型配置、输入与输出 token、缓存读取/写入 token（供应商有提供时）、首 token 延迟、总延迟、工具费用和成功率。

| 实验 | 改变因素 | 要回答的问题 |
| --- | --- | --- |
| C1 | 重复稳定前缀，只追加工具结果 | 正常迭代是否获得复用 |
| C2 | 本地设备在线变为离线 | 系统提示和工具定义是否意外变化 |
| C3 | 文件 Backend 与沙箱 Backend 切换 | `execute` 可见性是否改变前缀，为什么生产应避免这样切换 |
| C4 | 大结果直接返回与数据集外置 | token、延迟、任务正确率如何变化 |
| C5 | 全量工具与按需发现 | 发现成本是否低于减少的输入和错误成本 |
| C6 | 保留长历史与压缩恢复 | 总成本和正确率的平衡点 |
| C7 | 简单任务启用与禁用子 Agent | 子任务是否带来实际收益 |
| C8 | 长时间本地等待后恢复 | 缓存过期后是否仍能正确续跑，成本如何变化 |

缓存指标按供应商计费字段解释，不把跨厂商 token 字段直接等同。不能以某一次命中或未命中判断设计优劣；需在可比条件下重复测量，并将执行器和数据权限变化纳入观察。

## 8 验收标准

原型阶段优先验证以下事实：

- 至少完成一类开发时未提供专用报表函数的跨模块分析，并交付实际运行生成的产物。
- 关键数字可由记录的数据快照、查询和脚本重算。
- 权限测试集中，直接工具、代码、子任务、本地执行和报告下载都不能越过授权边界；这不等于证明系统不存在其他漏洞。
- 故障注入测试中，外部写操作结果未知后能核对真实状态，且没有重复单据。
- 设备离线、登录失效和字段缺失有明确状态，不产生伪造成功结果。
- 压缩与重启后能继续任务；文件、批准和工具调用不会因 checkpoint 恢复被错误重放。
- 记录每个成功任务的成本、延迟、人工介入和数据质量，形成首轮基线。

生产 SLA、可接受错误率、并发和成本目标由首轮真实数据及业务风险确定。安全关键测试失败必须阻止对应能力上线；总体平均成功率不能掩盖越权或重复写入。

## 9 第一批需要补充的信息

1. ERP API 与认证文档、可用沙盒、业务字段说明和历史数据覆盖。
2. 能否获得批量导出或授权分析视图，以及允许的数据更新延迟。
3. 首个电商平台、目标产品类别、需要采集的字段和已有账号使用方式。
4. 客户设备系统、浏览器、安装权限与企业软件策略。
5. 模型服务地区、企业数据出境或本地处理要求、日志与证据留存策略。
6. 第一批用户角色及可自动执行、需要审批的具体业务动作。

在这些信息未齐备时，可以完成框架、合成数据研究和协议原型；涉及真实平台覆盖、账号行为、生产权限和成本承诺的结论须等待实际接入验证。
