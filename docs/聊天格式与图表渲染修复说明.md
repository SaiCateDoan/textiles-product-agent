# Markdown 与聊天图表修复

日期：2026-11-06。

原来的回复直接转义为纯文本，Markdown 没有解析。图表只在报表工作室中绘制，聊天只显示报告链接；恢复对话时又只读取最后一次任务的执行记录，导致早期报表不出现在结果区。

现已修复：

- 助手回复通过本地 Marked 解析 Markdown，再经 DOMPurify 标签/属性白名单清理。支持标题、强调、列表、引用、代码、链接和表格，外部链接隔离 opener，禁用脚本与事件属性。
- 聊天和报表工作室共用 `frontend/renderers.js`，从真实报表数据构建 ECharts 图形，不执行模型输出的代码。
- 成功的 `create_report` 结果直接显示为聊天卡片。历史会话读取所有轮次的工具结果，实时事件和历史加载按报表 ID 去重。
- 卡片支持切换展示类型、CSV 下载、打开报表工作室。聊天顶部提供报表快捷入口；刷新保留当前会话。
- 图表随容器尺寸变化重绘；切换页面、视图或重新加载对话时清理旧图表与观察器。
- 模型工具契约要求显式提供 `chart_type` 和 `sql`，明确要求图形时使用报表工具而非 Markdown 表格替代。

验证结果：

- `npm run test:frontend`：13 项通过，覆盖 Markdown、HTML 清理、历史/实时卡片、去重、表格转图、8种图表/表格、聊天到工作室集成。图形测试使用真正 ECharts SVG 输出。
- `python -m pytest -q`：31 项通过。
- 真实 DeepSeek 返回 Markdown 结论并生成柱状图、饼图，快照与保存后的报表一致，无业务写操作。原始证据见 [定向验证](聊天格式与图表渲染验证轨迹.json)。
- 真实浏览器验证了原历史会话中的图表恢复、饼图切换、Markdown 排版、新图表展示、报表快捷入口及刷新恢复。刷新后检测到2张报表、2个 canvas、1个 Markdown 二级标题和9处加粗。

使用方式：刷新本地网页，进入“智能助手”，打开历史对话即可查看已生成图表；无需重新生成已有报表。对于从未调用过报表工具、只有文字的回答，可继续要求助手“生成柱状图和饼图”。
