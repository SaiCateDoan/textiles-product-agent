# 经营总览性能修复

## 原因

加入岗位权限后，原总览实现逐个查询可见指标和数据列表：管理员一次页面加载触发11次串行内部 HTTP 请求，销售6次，生产8次。

每次适配层请求都会新建并销毁 `httpx.AsyncClient`。在本机 Windows/Python 环境中，创建客户端需要约300–400毫秒，性能分析定位到 SSL 证书加载（一次 `load_verify_locations` 约286毫秒）。即使目标是环回 HTTP，默认客户端初始化仍会准备 SSL 上下文。这一固定开销被总览的串行请求放大。

每个查询还会重新读取登录状态、从 SQLite 构建完整的岗位可读数据副本。实测单次身份解析约2–3毫秒，权限 SQL 查询约3–5毫秒；它们不是本次秒级延迟的主要来源，但重复构建也没有必要。问题来自权限版本的请求方式变化，而不是读取所有账号或密码校验。

## 修改

- `ERPAdapter` 在 Agent 服务启动时创建一个异步 HTTP 客户端，服务关闭时释放；多个请求复用连接池。没有关闭证书验证。
- 内部令牌与当前用户会话仍逐次设置在请求头，不将用户身份写入共享客户端默认头；每次调用继续重新验证当前登录。
- 总览改为一次内部 `GET /dashboard` 调用。ERP 后端验证用户，创建一次权限数据副本，全部指标与数据列表在这份快照上查询，最后释放。
- 复用原只读 SQL 执行器的表白名单、指令预算、列名和结果行数检查。每条查询独立重置指令预算。
- 未缓存跨请求业务结果、授权或快照，因此权限撤销与后续业务变更继续生效。前端响应结构和岗位可见内容保持一致。

## 实测结果

本机、同一业务数据库，每项3次 HTTP 请求的中位数；不包含登录操作及前端绘制时间。原始样本见 [dashboard-performance.json](dashboard-performance.json)。

| 岗位 | 修复前总览 | 修复后总览 |
| --- | ---: | ---: |
| 管理员 | 3784.27 ms | 26.96 ms |
| 销售 | 2002.49 ms | 24.10 ms |
| 生产 | 2855.80 ms | 23.80 ms |

独立 SQL 接口同样受益：三个岗位的中位数从约301–424毫秒降至约23–26毫秒。

复现（先启动 Demo；仅登录、读取并退出，不修改业务数据，不打印密码）：

```powershell
.\.venv\Scripts\python.exe scripts\benchmark_dashboard.py --samples 3 --output .runtime\dashboard-benchmark.json
```

支持 `--base-url`、`--accounts` 和 `--samples`，可测量使用独立数据目录的实例。初始密码已修改时，需提供有效的本机账号文件。

## 回归验证

`python -m pytest -q`：47项通过，包括原业务、SQL、权限和 Windows 启停测试。新增检查覆盖7个岗位各自仅调用一次内部接口、仅构建一次权限快照、可见字段和客户范围、业务写入后的总览刷新，以及共享客户端并发身份隔离、撤销登录后拒绝请求、关闭和重新启动客户端。
